# 影视内容发行权窗口与独占冲突审阅平台

源提示词编号：10。维护作品、权利类型、地区、语言、窗口、独占和次级授权，联动时间轴与地区矩阵，检测重叠、交叉、倒挂和独占冲突，支持批量调窗、版本差异、评论锚点、审批和追溯导出。

## 技术栈

Next.js App Router、Chakra UI、Zustand、TanStack Query、tRPC、Zod、TypeScript。

## 批量调窗的并发与恢复规则

发行部与法务同改一份草案时，批量调窗不再直接落库，而是走“可恢复批次”：

- **先预览**：批次基于每个授权窗口的当前版本（`rev`）生成预览，提交前不改动任何窗口。
- **乐观锁提交**：逐笔比对窗口当前版本与预览基准版本。
  - 同一授权窗口已被对方改过 → **保留对方版本，这笔挂起**，批次继续处理后续窗口；
  - 两笔同时提交同一版本 → 按批次排队序号确定性地**只允许一笔生效**，另一笔挂起；
  - 挂起笔可“按对方版本重订”后再次提交。
- **可恢复**：写入失败立即中断并保留批次；恢复时从断点继续剩余窗口，**已生效窗口不会重复顺延**。
- **按最新批次显示**：冲突矩阵始终基于窗口当前版本重算，待决条款逐笔标注批次处置，审批包（`lib/approval.ts`）在导出瞬间现算冲突并随包留痕挂起/失败笔，存在失败或高风险冲突时标记不可审批。
- **旧稿兼容**：没有版本号的窗口（`rev === undefined`）按第 0 版处理，页面显示“旧稿”，状态流转保持原口径；旧的 v1 本地缓存不会被误合并（存储键升级为 v2）。

席位可在“授权窗口”页右上角切换（发行部 / 法务）以模拟对席并发修改；批次面板可向指定窗口注入一次写入失败用于演示恢复。

## 测试

```bash
npm test            # 乐观锁、同版本竞争、失败恢复、旧稿兼容、审批包现算等场景
npm run build
```

核心纯逻辑在 `lib/batch.ts`，场景用例在 `server/batch.test.ts`。
